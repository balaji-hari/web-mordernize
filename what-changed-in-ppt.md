# What changed in `web-modernize-presentation.pptx`

This file captures every slide-level change applied when rebuilding the leadership deck for **plugin v0.10.0**. The deck's audience is leadership — the framing throughout is "plugin vs. manual prompting value" — so each change is described in terms of what leadership now sees.

The PPT is regenerated by running `python build_presentation.py` from the repo root. The source of truth is `build_presentation.py`; the `.pptx` is the build output.

- **"Stacks Supported" technical card body rewritten.**
  - Before: *"First-class auto-detection and scaffolds for ASP.NET, Java JSP, AngularJS, classic PHP, ColdFusion → React, Next.js, Vue 3, Angular, SvelteKit (+ optional API/DB). Any other source or target stack works in 'custom' mode where the team supplies the scaffold."*

  - **Why for leadership:** quantifies coverage (17 vs. 14, vs. "first-class for 5"), names the modern targets executives recognize (Astro, Nuxt, Remix, Hono), and reframes "custom mode" as a graceful path rather than an escape hatch.

### Slide 6 — What the plugin adds to Claude Code

**Two new rows added to the before/after comparison table (now 8 rows, was 6):**

1. **"Setup ergonomics"** — *Without:* developer hand-edits a config file with no validation until later. *With:* `/analyze` walks the team through every required choice with stack-aware recommendations.
2. **"Tool discovery"** — *Without:* developer memorises slash commands or hunts through docs. *With:* type plain English — *"what's next"*, *"let's plan"*, *"stuck lock"* — and the right skill auto-fires.

**Why for leadership:** the two rows directly capture the v0.10.0 deltas (Parts 1 and 2 of the design doc) inside the existing rhetorical structure that leadership already understands. The "Plugin Adds X" framing reinforces the deck's central message.

### Slide 7 — Natural Language + Pluggable Framework Library  (NEW)

**Brand-new slide.** Two-column layout:

- **Left half (cobalt accent): "Talk to it naturally."** Description card + table of 6 NL utterance → skill examples (*"what's next"* → `/next`, *"let's plan it"* → `/plan`, *"stuck lock"* → `/unlock`, etc.). Demonstrates Part 2's NL routing concretely so leadership sees what "natural language" means.
- **Right half (teal accent): "Pluggable Frameworks."** Description card + 4 large-number badges:
  - **17** — legacy source stacks auto-detected
  - **14** — modern targets with full scaffold recipes
  - **1** — file to add a brand-new framework
  - **0** — plugin code changes needed for the new framework
- **Full-width lower band (navy): "Unknown-tech path."** Three boxes covering the three places unknown tech surfaces — source unknown (`/analyze`), target unknown (`/scaffold`), auth unknown (`/auth`) — and the graceful behavior at each.
- **Takeaway strip (cobalt):** *"Friendlier to onboarding. Quieter when the right answer is obvious. Never stuck on an unsupported stack."*

**Why for leadership:** packages Parts 2 and 3 into one slide that frames the v0.10.0 release as continuous investment in usability (NL) and extensibility (framework library). The badges turn the underlying engineering into easy-to-quote stats for downstream presentations.

# Demo-readiness pass — added Slide 7 "Risk, Safety, and Reversibility"

Preparing the deck for a live leadership demo (mixed engineering + business audience). The deck argues "plugin is better than plain Claude prompting," but the existing slides scatter risk/safety claims across slides 3, 6, and 9. For a leadership audience — especially business leaders new to AI-generated code — the natural question *"what if the AI gets it wrong?"* needed a single slide that answered it head-on.

User-confirmed scope: this single change only. Skipped were a quantified-value/ROI slide (user opted for qualitative only) and a demo-flow narrative slide (deferred). The closing slide's pilot CTA was also left as-is.

## Slide-by-slide diff

### Slide 7 — Risk, Safety, and Reversibility  (NEW)

**Brand-new slide.** Inserted between Slide 6 (Plugin vs Raw Claude Code) and the former Slide 7 (NL + Frameworks). Placement rationale: Slide 6 just told the audience the plugin is better than raw prompting; the natural follow-up — *"OK, but is it safe?"* — is most pressing at exactly that moment.

**Layout:** three-column card grid with a 2-line bottom takeaway band.

**Content (3 cards, qualitative claims aligned to existing plugin features):**

1. **"Nothing is one-way"** (cobalt accent) — covers `/rollback`, two-step `/abandon`, git-tracked actions, per-unit notes.
2. **"Nothing ships unverified"** (teal accent) — covers `/verify` as a hard gate, `failure.diagnostic_history`, `/retry --with-prompt`.
3. **"Nothing is hidden"** (green accent) — covers state-in-git, `/status`, per-unit file split, commit-per-developer auditability.

**Bottom takeaway band (navy):**
- Headline: *"Every AI-generated change is reviewable, reversible, and auditable"*
- Subline (italic, teal): *"Not a one-way bet on the model getting it right the first time."*

**Why for leadership:** answers the safety question directly with a unified narrative pulled from real plugin features. Each claim maps to a concrete slash command or state artifact (auditable in `git log`, etc.) — nothing speculative.
