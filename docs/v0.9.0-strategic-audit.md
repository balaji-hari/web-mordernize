## The three coherent architectures

### (1) Workflow-only

- Strip everything except state machine + gates + recovery + hooks + workflow skills.
- Agent fends for itself on every framework decision via WebSearch.
- **Pro:** zero framework-version maintenance, scales to any new stack without plugin changes.
- **Con:** every team hits the passlib / hatchling / Spring-health / `reflect-metadata` bug for the first time, every time. Quality varies per Claude session.

### (2) Workflow + minimal durable knowledge **(RECOMMENDED)**

- Workflow plumbing (unchanged).
- `agents/permanent-gotchas.md` pruned to the ~5-7 entries Claude **cannot** discover via WebSearch (crashes-on-first-run, silent-wrong-behavior).
- `templates/permanent-gotchas/<stack>/` — **dropped entirely.** Agent regenerates templates at scaffold time from the catalog text.
- `skills/auth/SKILL.md` per-stack hashing table — **dropped.** Agent picks default given the catalog's "no passlib" entry.
- `skills/plan/SKILL.md` UI framework enum — **dropped.** Accept any non-empty string.
- Stack defaults table — **kept** (ports/Node-min/CORS allow-list, ~10 lines, durable).
- **Pro:** ~70% smaller than today. Catches the embarrassing first-run failures. Doesn't age (durable facts only).
- **Con:** still some framework-specific surface area. Catalog needs occasional review (e.g., when passlib finally fixes the bcrypt-4 issue, drop that entry).

### (3) Status quo (v0.8.3)

- Workflow + thicker catalog + 9 template files + per-stack tables.
- **Pro:** highest first-run quality across all supported stacks.
- **Con:** still more maintenance than the user wants. The audit shows much of it is discoverable-via-search.

## Design principles established this session (durable)

These are saved as memory entries (`~/.claude/projects/.../memory/`):

1. **No schema migration code, no back-compat shims** — plugin has no users yet; schema bumps require fresh `/init`.
2. **Teams coordinate offline** — multi-dev design assumes standup-style claiming, not in-tool coordination.
3. **Prefer pattern-level rules over per-scenario features** — when a translation gap surfaces, add a shape-agnostic rule to `permanent-gotchas`, NOT a dedicated synthetic unit / required field / skill.
4. **Customers want latest framework versions** — pin only when an LTS line is required (via `migration.md §8 Constraints`).

A v0.9.0 prune should be consistent with all four — Architecture (2) explicitly is.

## The audit criterion (one-liner)

> **Keep something in the plugin only if the agent provably can't discover it on its own** — i.e., the bug crashes before a search would naturally happen, OR the behavior is silently wrong (no error to search for). Everything else goes.
